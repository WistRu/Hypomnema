## Append-only commands and evaluation separation

Server tests prove create, rename, aliases, override, merge and split through
the closed command catalog. Each command stores a normalized payload
fingerprint and receipt in the same transaction as its immutable event. Exact
replay returns the original receipt; conflicting key reuse fails. Rules,
assignments and resource lifecycle history are never rewritten, while heads
select current state. Merge preserves source identity as `merged`; split leaves
the source active and records new current assignments.

The review queue returns the exact `currentAssignmentId` CAS token for
ambiguous rows and `null` for unmatched rows. Manual override accepts the exact
token and rejects a stale token with `RESOURCE_ASSIGNMENT_CONFLICT`.

User evaluation is a separate nullable `1..3` preference. Local writes are
server-stamped `user/manual`; the trusted agent route is server-stamped
`agent/on_behalf_of_user`, uses a separate idempotency namespace and rejects
spoofed provenance. No AI assessment is represented as user evaluation.

## Context, privacy and restart

One lifecycle/search/privacy engine serves typed page and resource subjects.
Resource context passes create, edit, withdraw, restore, review, search,
pagination, idempotent replay and catalog restart tests. Local routes can read
`local_only`; public/agent/MCP projections contain only shareable entries.

Privacy-negative tests compare hidden-vs-absent agent projections byte for
byte. They expose no private body, private count, internal context ID, revision
or idempotency key. Resource context and command routes retain the same
HttpOnly local-session boundary established in G2. Agent routes do not accept a
local capability.

## Library UX

Resources remain a facet of Library, not a new top-level surface. The sidebar
switches between Topics and Resources while `selectedTopic` and
`selectedResource` remain orthogonal. Both filters have independent chips and
compose through canonical, bulk and physical-copy Library calls. Resource
selection is URL-backed (`?resource=<id>`) and survives back/forward while
preserving sort, pagination and the unrelated filters.

The compact Resource header is the accepted inline-header alternative to a
table column. It distinguishes logical pages, browser rows and physical open
copies; shows all-time on-screen/active-use totals with honest unknown
coverage; edits protected-aware aliases with CAS; keeps user evaluation
separate from unavailable AI assessment; and uses a keyed context subject so
an A-to-B selection cannot leak a draft or visibility choice.

The paged review UI never auto-assigns. It supports create and exact manual
override, including a validated exact-ID target beyond the first 200 active
resources. Weak sensitive signals keep the conservative access class.
Feature discovery is exact-`true` and fail-closed. Graph and physical-tab
activation behavior are unchanged. New EN/RU Resource surfaces pass the key
audit and axe serious/critical count is `0`.

## MCP contract

With `features.resources === true`, MCP registers `list_resources`,
`get_resource`, `get_resource_context`, `set_resource_context` and
`set_resource_evaluation`, plus `tabhub://resource/{id}`. Missing/false legacy
feature payloads register none of them.

All projections are bounded: aliases `50`, topic paths `50`, current/history
entries `20`, and bodies `4000` characters. Truncation metadata refers only to
already-public/shareable arrays. A 10k-alias/large-context adversarial test
proves the bounds and local-only canary absence. The stdio protocol test uses a
temporary schema-20 REST runtime and proves list/get/activity/counts,
shareable write/replay, trusted evaluation/replay and the Resource URI.
