## Corrective audit and reacceptance

After C90b began integrating the closed purge seam, it proved that the
executor's allowlist covers only the 49 guard-bearing research/G9 tables. It
cannot include ordinary page-owned rows required by decision #9 point 32, such
as `context_entries`, `context_entry_reviews`, `tab_session_intents`, page
priority/activity/preferences and Resource-link rows. The executor also expects
every target to consume a one-shot guard authority, so adding ordinary tables
to the existing guard manifest alone would not work.

The independent auditor confirmed this as a verified C90a `P1`, temporarily revoking the
initial acceptance with `P0/P1/P2/P3=0/1/0/0`. A separate C90b transaction is
not permitted because point 33 requires exact deletion, sensitive-key removal,
lifecycle successor and result to commit together. Corrective C90a must freeze
a complete purge-target catalog with canonical PK/FK-safe ordering and guarded
status, then delete guarded and ordinary targets in the executor's one owned
transaction while issuing authority only for the guarded subset. Combined
logical-page inventory, ordering, rollback and recreation tests are mandatory.

The corrective implementation now freezes 63 exact executor targets: 56
authority-guarded tables and seven ordinary tables. Seven schema-24 legacy
guards for page priority and Resource assignment/resolution rows were replaced
with exact one-shot-authority guards while preserving their predicates and
error messages. The true ordinary set is exactly `ai_jobs`, `context_entries`,
`context_entry_reviews`, `logical_page_activity_daily`,
`logical_page_importance_migration_audit`, `logical_page_preferences` and
`tab_session_intents`. The executor fingerprints this catalog, validates
nonincreasing FK-safe order and applies exact existence/delete/anti-recreation
checks to every target; authority and per-row fences exist only for the guarded
subset. An all-14-category logical-page fixture proves atomic rollback and
success while retaining page/report/run/Resource identities.

The same auditor then recomputed the corrected freeze and returned
`P0/P1/P2/P3=0/0/0/0`, mandatory `UNVERIFIED=0`, verdict `ACCEPT`.

## Second cross-packet revocation

C90b's real coordinator-to-final-run purge test then exposed a second verified
C90a seam. A run command is anchored to one subject generation and the executor
retires only that root generation. The committed exact deletion plan may also
contain the final descendant `research_runs` row, whose still-active generation
is updated by `ON DELETE SET NULL`; the generation immutability guard correctly
rejects that update. The independent auditor reproduced the exact
`privacy subject generation is immutable` error and revoked C90a again with
`P0/P1/P2/P3=0/1/0/0`.

Multiple child purge commands are not compliant because they introduce partial
commit/crash/idempotency states. Preserving the final C81 run contradicts the
required coordinator/final descendant graph. Second corrective C90a must bind
every exact targeted run generation and stable token into the command's
immutable lifecycle commitment, create permanent root and descendant
tombstones, retire all planned generations before the first run deletion, and
commit deletion, authority cleanup, lifecycle validation and one result in the
same transaction. Multi-run success, partial-retirement/mid-delete rollback,
tombstone permanence, nonreuse/new-generation behavior and replay/conflict
tests are required.

## Final second-corrective reacceptance

The final correction commits the exact singleton or coordinator-to-final run
lifecycle set in the command-creation statement. Each target binds generation
ID, stable generation token and run ID into an immutable count and canonical
SHA-256. For a two-target graph the freeze independently revalidates the C90
coordinator and C81 final roles, Resource lineage, completed directed handoff
and its immutable terminal receipt; it does not rely only on the ordinary
handoff insert guard. Reverse, cyclic, incomplete, unreceipted, inactive and
extended graphs abort command creation without leaving command or lifecycle
rows. Legitimate standalone C81 and C90-without-handoff singletons remain
supported.

Finalization exact-matches lifecycle identities to every committed
`research_runs` deletion row, creates permanent tombstones for the whole set,
retires and detaches every generation before the first run deletion, then
commits the 63-target deletion, authority cleanup, terminal lifecycle and one
result/status atomically. Three injected failure points prove full rollback;
exact replay performs zero writes and divergent replay conflicts.

Failed commands retain their immutable lifecycle commitment but no tombstone
and leave the generation active. Historical lifecycle identities may therefore
appear under a fresh retry command, while the lifecycle insert guard rejects
any overlap owned by another `pending|waiting` command through either root or
descendant. A successful retry retires/tombstones each generation once and
blocks all later reuse.

Two intermediate second-corrective candidates were revoked during independent
review: first for accepting a two-node reverse cycle under a damaged ordinary
handoff guard, then for missing semantic handoff readiness and failed-command
retry. Both findings received exact RED→GREEN tests before this final freeze.

## Accepted boundary

C90a introduces migration `025_live_acquisition.sql` and the server/shared
foundation required by the accepted G9 revision-6 contract. The packet owns the
schema and deletion-closure inventories, guarded source bridge, captured/live
source contracts, filtered claim/recovery foundations, pure Resource preview,
generation/history identities and the closed privacy-purge transaction
executor. Network acquisition, target enumeration, policy and orchestration
remain C90b work; W90 remains closed until C90b is accepted.

The corrective executor boundary is deliberately declarative. The only purge
entry point accepts an exact ordered table/primary-key plan plus immutable
result data. It exposes no callback or SQL seam. Before mutation it verifies
autocommit and foreign keys, the command's committed target count and canonical
SHA-256, and existence of every exact frozen-catalog row. It owns
`BEGIN IMMEDIATE`, tombstone/fence/one-shot authority creation, exact deletion,
anti-recreation checks, authority consumption, lifecycle successor creation,
terminal result and commit. Any exception rolls the whole operation back and
clears connection-local authority state.

Strict descriptor snapshots reject functions, accessors, thenables and proxies
without evaluating attacker-controlled input. Completed and failed plans have
separate exact shapes. Run, logical-page generation and Resource history-epoch
retirement/successor semantics are covered, including zero-target cases and
permanent-row protection.
