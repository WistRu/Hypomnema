## Atomicity, retry and recovery proof

Publication re-reads and validates the entire corpus plus parent inside the
ledger-owned `BEGIN IMMEDIATE` transaction. Mutation of an included source —
including an uncited source — rejects publication with `JOB_INPUT_UNAVAILABLE`
and leaves both report and success transition absent.

The exact attempt-3 internal stale guard is the only material-free publication
path. It requires the canonical provider metadata, empty evidence, canonical
dossier and an atomic `readAuditForJob` fingerprint/coverage match. A forged
stale conclusion, failed audit read or redacted dependency rolls back without a
report. Normal fresh, partial and successful publications always use the full
material reader.

Executable race and restart coverage proves:

- cancellation after binding but before provider I/O performs zero remote calls;
- lease loss while durably binding a returned request ID aborts the started
  response before body consumption and publication;
- response-body stream errors and aborts are non-retryable once response headers
  have been received, avoiding an unaccounted duplicate charge;
- provider retries honor only strict delta-seconds or valid IMF-fixdate
  `Retry-After` values; malformed values are rejected and redirects are disabled;
- a real file-backed process loss after durable usage checkpoint is recovered
  after lease expiry, repeats the provider call once, and publishes exactly one
  report with exact cumulative usage across interrupted and successful attempts;
- both priority→research and research→priority adapter ordering delegate to one
  real global recovery owner, yielding one interrupted attempt and one recovered
  event rather than double recovery.
