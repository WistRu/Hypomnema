## Packet outcome

`A80` exposes captured-only research to a stateless MCP client through five
strict tools:

- `start_research`;
- `get_ai_job`;
- `cancel_ai_job`;
- `list_research_reports`;
- `get_research_report`.

`start_research` performs exactly one `POST /api/agent/research/start`. It does
not perform a client-side preflight, poll, navigate, capture, fetch a page or
retain an in-memory replay cache. Its closed snake-case input maps only to the
accepted C82d declarative command. Derived approval fields, parent report,
capture intent, estimate, approval fingerprint and caller-selected provenance
are absent and rejected before HTTP.

## Capability, privacy and protocol proof

Capability discovery has three explicit states. A legacy server that omits the
research capability exposes no research surface. `research=false` preserves the
three job/report readers while hiding start and cancel. `research=true` exposes
all five tools. No research MCP resource URI was added.

Start is annotated non-destructive, idempotent and open-world. Cancel is
destructive, idempotent and closed-world. All readers are read-only. Job,
report and target identities are checked fail-closed, exact REST routes are
used, and research transport failures expose only a typed error code rather
than server messages or private response material.

A built stdio transcript proves one bounded REST operation per tool, no hidden
polling and no capability/cookie/authorization-header forwarding. Privacy
canaries do not appear in tool output. A real schema-24 application proof starts
research through MCP, changes the corpus access class, constructs a fresh MCP
server and REST adapter, then replays the exact input/key. C82d returns the same
job while job, run and receipt counts remain unchanged.
