## Packet outcome

- separate trusted-loopback `/api/agent/research/*` preflight, run, report-list,
  report-detail and research-cancel routes do not receive or reuse the first-party
  HttpOnly local capability;

  accepts only a bounded explicit `authorizationRef`; caller-supplied actor or
  method fields are rejected by strict schemas;

  to access class and origin digest, while the agent projection structurally
  omits that display;

  title, excerpt and raw locator material before it reaches an adapter;
- `GET /api/logical-pages/:id/resource-resolution` returns the persisted closed
  four-state resolution without URL inference or writes.

## Durable command replay and atomicity

Migration 024 now owns one append-only `agent_research_command_receipts` table.
It stores only a domain-separated idempotency-key hash, closed operation,
canonical declarative request fingerprint, authorization-reference hash,
research-job FK and timestamp. Raw keys, authorization references, questions,
corpus and report material do not enter the receipt.

The ledger checks a receipt before any mutable corpus validation. Exact start
replay after corpus drift returns the same original job identity with its
truthful current status; changed request, authorization or operation fails with
`IDEMPOTENCY_KEY_CONFLICT`. First start plus receipt and first cancel transition
plus receipt each execute in one ledger-owned immediate transaction. Injected
receipt failures prove complete rollback for both paths. Exact cancel replay
creates no second transition or event.
