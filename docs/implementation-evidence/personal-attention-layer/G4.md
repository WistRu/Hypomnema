## Ingest and rollup invariants

Server tests prove:

- an interval crossing UTC midnight is split proportionally, with deterministic
  remainder allocation and exact conservation of both source totals;
- valid elapsed duration is capped at `120000 ms`; a longer interval is rejected
  by the shared contract before any database work;
- every accepted interval that spans multiple UTC buckets conserves totals and
  every bucket satisfies `engaged_ms <= foreground_ms`;
- exact replay changes totals by zero, a conflicting replay is rejected, and a
  lower/out-of-order sequence is rejected consistently;
- the first observed sequence establishes an unknown baseline; gaps are counted
  only between observed cursor heads, with persistent gap/missing/duplicate/
  out-of-order metrics surviving restart;
- future-ended and invalid events are rejected before persistence, while the
  database constraints remain a final atomic guard;
- the daily writer and finite readers are independently configured and default
  off. Reader exposure additionally requires the active writer, Resources and
  schema 21, preserving accepted G3 all-time reads under every G4-off profile;
- delayed writer enable starts coverage at `max(now, availability epoch)`. An
  unchanged enabled restart is a no-op; disable/re-enable creates a new
  continuous epoch and atomically purges same-day/future contamination;
- pre-epoch queued intervals add zero daily activity, crossing intervals add
  only the proportional suffix without moving discarded-prefix remainder, and
  lifetime totals/cursor still process the original accepted interval;
- transition and runtime clock regressions, missing/corrupt/relationally
  inconsistent lifecycle state and failed purge abort without partial writes;
- `7d` and `30d` are UTC calendar windows; bounds and the persisted coverage
  epoch are returned explicitly;
- finite windows read only daily buckets. Old lifetime totals remain available
  only to `all`, so pre-epoch finite history is never invented;
- resource rollups use current logical-page membership. Reassignment moves the
  page once, and duplicate browser/physical copies cannot multiply its totals;
- forced failure rolls back daily totals, lifetime totals, metrics and cursor as
  one transaction.

The shared response validates non-negative integral totals, active-use not
exceeding on-screen time, finite-window coverage presence and ordered bounds.
The additive optional feature capability `activityWindows` preserves old
clients and is advertised true only for explicit reader + active daily writer
and Resources + `schemaVersion >= 21`.

## Web UX and accessibility

The selector is confined to the existing ResourceHeader in Library; Graph,
navigation and URL state are unchanged. It defaults to `all`, resets on a new
resource, and keys reads by both resource ID and window. Late/aborted responses
cannot replace the newly selected resource/window.

The UI keeps `On screen` and `Active use` distinct. Finite coverage is labelled
full only when `coverageStart <= windowStart`; otherwise the persisted partial
start date is shown. All-time coverage shows its tracking date or says that the
start is unknown. A valid zero renders as `0s`, not as missing data. Loading,
background refresh failure and retry remain distinguishable.

`activityWindows` omission or false value performs zero window requests and
keeps the accepted all-time G3 presentation. Tests cover native fieldset/radio
keyboard behavior, EN/RU labels, resource reset, request races, all coverage
states, zero values, errors and absence from Graph. Axe serious/critical
violations are `0` in both locales.

## REST and MCP parity

The typed adapter calls exactly
`/api/resources/:id/activity?window=7d|30d|all`, parses the shared schema and
rejects a mismatched resource ID or window. The separate read-only
`get_resource_activity` tool defaults to `all`; it does not change
`get_resource` or `tabhub://resource/{id}`.

The tool is registered only when both `resources === true` and
`activityWindows === true`. Omitted, false, malformed and feature-fetch error
cases fail closed before any activity call or mutation. Output text and
`structuredContent` are the same strict object containing only `resourceId`,
window totals, coverage and UTC bounds. Privacy negatives find no `local_only`
body or existence signal.

The built stdio integration test starts a disposable schema-21 REST server on
port `0`, ingests `10000 ms / 4000 ms`, then proves exact REST equals MCP JSON
text equals MCP structured content, including dynamic epoch and bounds.
