# Architecture decisions

- 2026-08-08: Use ordered SQL migration files and `better-sqlite3`; schema ownership stays in the server package and callers receive a ready database through one creation interface.
- 2026-08-08: Keep shared runtime schemas in `@tabhub/shared`; adapters (extension, web, MCP) consume the same validated wire contracts.
- 2026-08-08: Tab events trigger a debounced full-browser snapshot because the specified ingest contract is snapshot-based and only a full set can close missing tabs correctly.
- 2026-08-08: URL normalization removes fragments and case-insensitive `utm_*` parameters while preserving every retained parameter and its order; no other tracking parameters or path forms are changed in v1.
- 2026-08-08: Use a contentless-delete FTS5 table synchronized by SQLite triggers; canonical text stays in `contents`, while title/content/summary indexing remains atomic across REST, worker, and future MCP writes.
- 2026-08-08: Convert user search text into quoted Unicode tokens joined with `AND`, preventing raw FTS syntax errors while retaining predictable keyword semantics.
- 2026-08-08: Keep MCP as a stateless REST adapter using the split MCP TypeScript v2 stdio packages; all MCP tag mutations are recorded with `assigned_by = 'agent'`.
- 2026-08-08: Rename ambiguous duplicate root tags during the v3 migration, then enforce root-name uniqueness in SQLite so concurrent local server processes cannot fork a tag path.
- 2026-08-08: Persist summary jobs and every provider attempt in SQLite, process one request at a time, and bind each job to a content revision so retries and restarts cannot attach stale output.
- 2026-08-08: Call Anthropic's Messages API directly with pinned configurable model IDs; resolve configurable token prices at request time so stored cost estimates follow the dated Sonnet 5 pricing transition without hidden SDK retries.
- 2026-08-08: Treat a null value in the tab patch's `customFields` map as deletion; this keeps arbitrary-field editing atomic without adding a second field-specific endpoint.
- 2026-08-08: Resolve tag filters as subtrees, so choosing a parent topic includes tabs assigned directly to it or to any descendant while preserving one canonical path vocabulary.
- 2026-08-08: Keep links directed and provenance-bearing in REST responses; UI writes `createdBy=user` and MCP writes `createdBy=agent` through the same server-owned catalog.
- 2026-08-08: Store one active 512-dimensional embedding space in `sqlite-vec` with cosine distance and provider/model/content-revision metadata; embedding calls are explicit, batched, bounded, and stale vectors are invalidated before reuse.
- 2026-08-08: Make inbox clustering deterministic with cosine k-means and local TF-IDF-style labels, so `cluster_inbox` can propose stable named groups without an additional LLM call or silently changing tags.
- 2026-08-08: Build graph payloads with a set-based server catalog, then use deterministic memoized topic-group layout, React Flow visible-element rendering, and cycle-safe outgoing `follows` traversal for the current-work branch.
- 2026-08-08: Reject non-loopback `TABHUB_HOST` values at startup because v1 deliberately has no authentication; production startup is documented through Windows Task Scheduler.
- 2026-08-08: Keep schema-valid snapshots below the Fastify body limit, compact superseded offline work, cap local queue storage, and dead-letter permanent HTTP failures so one bad payload cannot block later captures.
- 2026-08-08: Require a versioned explicit browser choice in each extension install; automatic capture waits for it, and a later change durably closes the old identity before opening the new one.
- 2026-08-08: Virtualize dynamically measured table rows with TanStack Virtual while retaining server pagination, native table semantics, and expandable summaries.
- 2026-08-08: Treat loopback as a browser security boundary: reject non-local Host and Origin values, block non-extension cross-site Fetch Metadata requests except top-level read-only navigation to `/app`, and deny framing to prevent DNS rebinding, request-triggered provider work, and clickjacking.
- 2026-08-09: Separate physical browser-tab instances from canonical page records: snapshots retain every occurrence, while tags/content/search/MCP/graph stay attached to one normalized page per browser. Automatic duplicate cleanup is limited to exact raw URLs within one extension installation, always preserves pinned tabs and one exact-copy keeper, permits active copies after explicit confirmation, and revalidates each target in the extension immediately before closing it.
- 2026-08-09: Route every physical-tab mutation through one session-scoped v4 local bridge command executor; destructive closes require a one-shot live preview, preserve pinned/control tabs, permit active tabs, revalidate both an exact-copy target and its named keeper immediately before removal, and durably refresh live Undo metadata before each removal. Keep the five newest Undo records discoverable through the probe for ten minutes, remove the legacy duplicate-close bridge path, read bulk selection in one database transaction, synchronize the catalog after mutations, and order compact workspace selections from authoritative current rows before optional close.
- 2026-08-09: Remove hard tab-count ceilings from snapshot ingestion and its offline queue, physical commands and duplicate plans, filtered Library selection and bulk mutations, workspace persistence/restore, and inbox clustering. Validate non-empty unique targets and exact identities, process the complete selection through transparent internal batches without silent truncation, and retain explicit byte/quota failures where the browser or transport has an intrinsic resource boundary.
- 2026-08-09: Render the Open Tabs duplicate filter from the exact-group endpoint rather than a flat occurrence page. Sort groups by copy count, paginate whole groups, show the chosen keeper first, label every candidate and pinned copy relative to that keeper, and let a title/URL search select a matching group without trimming any of its physical members.
- 2026-08-09: Make duplicate-group close controls candidate-only and fail closed. Bind every selected candidate to the server-designated exact-URL keeper, disable keeper/pinned row selection in duplicate mode, require the current browser/install/session, block confirmation when live preview is partial, and state the retained-copy count when multiple pinned copies prevent leaving exactly one.
- 2026-08-09: Supersede current-page ownership gating for duplicate close with an in-memory loopback command relay. Each configured extension maintains one heartbeat-backed WebSocket registered to its exact browser/install/session; the UI sends only close-preview, confirmed close, and Undo to that owner. The relay never persists or automatically retries commands, rejects stale scopes and non-TabHub destructive HTTP origins, and reports post-dispatch disconnects/timeouts as outcome unknown. The owning extension retains the one-shot preview, exact URL/keeper, pinned, TabHub-tab, Undo, and pre-removal revalidation guarantees.
- 2026-08-09: Dispatch confirmed single-tab removals through a replenishing pool of at most eight instead of awaiting every browser removal serially. Keep target and keeper revalidation plus the live Undo-journal write ordered immediately before each dispatch, retain per-tab success/failure reporting and stable result order, and prune the provisional journal to successful removals after all bounded removals settle.
- 2026-08-09: Supersede the close-only relay contract with addressed browser-control protocol v3. Route activation, state inspection, every physical-tab mutation, workspace restore, and Undo to the exact browser/install/session that owns the target; prefer the same-page bridge only for that exact local scope. A bulk live action must address the complete selection in one connected scope and must never silently drop foreign or stale rows. Browser window IDs remain scope-local, and the remote transport does not invent a `TabHub window` destination when no controlling page exists in that browser. Direct and relayed live actions share one extension executor; each relayed command carries the server timeout as an execution deadline so a queued command cannot begin after the UI has already received an unknown timeout.
- 2026-08-09: Add one global exact-duplicate cleanup over the current browser/search filters. Read every matching group in one unpaged SQLite snapshot, preserve at least one exact keeper per browser/install/session, aggregate one live preview per exact scope, and require one user confirmation before concurrent per-scope closes. Exclude and disclose offline, invalid, changed, or expired scope plans; keep receipts and Undo scope-addressed, never retry an unknown close outcome, protect every open TabHub app tab on both direct and relay paths, and allow up to ten minutes for large close previews and confirmations.
- 2026-08-10: Treat every browser action on a canonical record marked open as a request to focus an existing physical tab, never as permission to open its URL again. Resolve the canonical ID to all live physical instances at click time, including for records rendered as closed, so a stale Library cache cannot create a duplicate. Prefer an exact scope controlled by the TabHub page and then the most recently used connected copy, and otherwise route the exact native tab ID through the owning browser relay. Fail closed when an open snapshot or its owner is unavailable; authorize a new URL tab only after a fresh resolver response confirms that a record rendered closed has no physical instances.
- 2026-08-10: Treat a middle mouse click on an open-tab surface as explicit confirmation to close exactly one physical browser tab immediately. Physical rows address that occurrence directly; Library, drawer, and graph records resolve one connected copy with the same deterministic chooser used for activation. Keep the existing live preview, one-shot confirmation token, exact URL/session revalidation, result verification, and durable Undo journal, but auto-confirm a complete one-target preview without a modal. Permit a pinned tab only when the preview carries the strict `explicit-single` intent; bulk and duplicate closes still protect every pinned tab, and TabHub control tabs remain unconditionally protected.
- 2026-08-10: Advance browser-control relay protocol to v4 for cross-process activation receipts while the v4 server temporarily accepts v3 extension connections during an ordered rollout. After the owning v4 extension activates the exact native tab, it reports the browser window title and bounds; the Windows server then performs and confirms an allowlisted native foreground handoff for Chrome, Edge, or Yandex Browser. Treat missing, denied, or ambiguous native matches as explicit failures instead of reporting false success or risking focus of another window, and require an interactive logged-on Task Scheduler session for this desktop operation.
- 2026-08-10: Publish the negotiated relay version and the direct probe's physical-command version so new UI actions can make capability-aware choices during the v3-to-v4 rollout. Treat a legacy direct probe without the new capability field as v3. Preserve v3 activation-compatible commands, but never dispatch the v4-only `explicit-single` middle-click close intent to a v3 extension; prefer a controllable v4 copy for canonical records and otherwise fail before dispatch with an explicit extension-reload instruction.
- 2026-08-10: Model tabs and hierarchical topics as typed knowledge entities so one relation table can enforce foreign keys for tab-to-tab, tab-to-topic, and topic-to-topic links. Keep topic containment in `tags.parent_id` and direct membership in `tab_tags`; graph v2 derives those structural edges instead of duplicating them as semantic relations. Preserve `/api/links` and `/api/graph` as compatibility projections while new clients use typed `/api/relations` and `/api/graph/v2` contracts with stable topic IDs.
- 2026-08-10: Keep a topic-filtered graph bounded without hiding cross-topic context: include direct semantic boundary nodes in the base projection, then load the selected node's complete undirected 1-5 hop neighborhood on demand across semantic, containment, and membership edges. Treat relation direction as metadata and traversal as undirected; do not materialize the full global graph merely to inspect a filtered node.
- 2026-08-10: Represent unclassified tabs with one protected root system topic named `Без темы`, enforced by SQLite triggers so ingestion, REST, MCP, graph, migrations, and direct database writes share the same invariant. Assigning any ordinary topic removes the system membership; removing or deleting the last ordinary membership restores it. Keep the system topic filterable but reject manual assignment, nesting, renaming, moving, unassignment, and deletion.
- 2026-08-10: Treat `Без темы` as a Library category and graph filter, not as a visible knowledge-graph entity. Graph selection may use its stored membership to choose unclassified tabs, but both graph projections omit the system topic, its membership edges, and its path labels so those tabs retain their original untagged graph semantics.
- 2026-08-10: Supersede fragment-stripping URL normalization: preserve `#fragment` in canonical page identity while continuing to remove case-insensitive `utm_*` parameters. Distinct SPA routes, messages, settings, and document anchors therefore remain separate Library/Graph records; migration v12 splits live and saved-workspace legacy records, reassigns physical/workspace references, and copies organizational metadata without duplicating captured content or semantic relations.
- 2026-08-10: Treat physical snapshots as leases rather than permanent proof that a tab remains open. When a modern extension submits a fresh full snapshot, evict physical rows from other installations of the same configured browser whose newest snapshot is more than 30 minutes old; preserve recently reporting parallel profiles and never delete their canonical Library records, saved workspaces, topics, content, or relations.
- 2026-08-10: Keep ordinary Open Tabs and Library pagination independent of snapshot arrival time. Use the fixed browser priority Chrome, Yandex, Edge, Other, then deterministically order unknown browser labels. Within one physical installation follow window and tab-strip position with an ID tie-breaker; within Library retain canonical insertion order. Preserve relevance order for semantic results and the safety-specific ordering of duplicate groups.
- 2026-08-11: Make Library the primary tab workspace and Graph its alternate visualization; remove the standalone Open Tabs entry from main navigation. Keep one canonical Library row per page, expose its exact live physical instances inline (one direct target or an expandable list for multiple copies), and separate canonical metadata selection from physical browser-command selection. Define the Library duplicate filter as canonical rows with more than one current physical instance, evaluated server-side before pagination; retain exact raw-URL comparison only for safe cleanup planning. Route activation, single close, bulk commands, previews, receipts, and undo through the full owning browser/install/session/tab identity. Ordinary mixed or offline selections fail closed as a whole; only the separately labelled global exact-duplicate cleanup may partition verified keeper-bound candidates by scope, disclose excluded profiles, and confirm the ready previews together.
- 2026-08-11: Keep Library full-text input safe as quoted Unicode `AND` terms, but treat every term as a prefix and combine FTS with literal, Unicode-normalized, case-insensitive substring matching on the canonical title/raw URL and every linked physical tab title/raw URL. Preserve browser, state, status, importance, duplicate, and topic filters as outer `AND` predicates. This makes partially typed names and copied URLs searchable without interpreting user punctuation as FTS syntax or rebuilding the FTS schema for the current collection scale.
- 2026-08-12: Model disposable pages as a personal retention lifecycle inside Library, not as a website taxonomy or a separate top-level workspace. Weak, explainable signals may place unrated Inbox pages in a review queue, but only an explicit user or agent decision can keep, defer, or forget a page. Forgetting is fail-closed: preview and close every exact physical instance in its owning browser scope, require complete correlated receipts, verify that no instance remains, then hide the canonical page in a seven-day reversible trash. Never delete automatically from a suggestion; cancel pending deletion when the page reopens, restore it as explicitly kept on request, and purge only closed expired records from a background server lifecycle.
- 2026-08-12: Protect `local_only` personal context with an explicit local-UI capability rather than Host, Origin, CORS, or the existing self-asserted relay scope. Production web access uses an opaque HttpOnly same-origin server session; an extension receives a per-installation bearer only after a short-lived, one-time, user-mediated pairing challenge. Store only credential/code hashes, bind extension credentials to installation and origin, support atomic rotation/revoke, never put secrets in URLs/logs/MCP, and return one generic failure for missing, invalid, expired, or revoked access. This boundary does not claim protection from malware or another process running with the same OS-user privileges.
